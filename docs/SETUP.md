# Setup

This guide explains how to import and run the Commercial OSINT Agent in n8n.

## Prerequisites

You need:

- A working n8n instance
- An OpenRouter account and API key
- A Tavily account and API key
- Internet access from n8n to the configured RSS feeds and APIs
- Support for the n8n LangChain/OpenRouter nodes used by the workflow
- The Tavily community node used by the workflow:
  `@tavily/n8n-nodes-tavily`

The current case study is configured for Digikala and its competitors.

## 1. Import the workflow

Import the sanitized JSON file into n8n.

Recommended repository path:

```text
workflow/commercial-osint-agent.json
```

The public workflow intentionally contains credential placeholders. Missing credentials after import are expected.

## 2. Configure OpenRouter

Create an OpenRouter credential in n8n and assign it to:

```text
19A - OpenRouter Model - Relevance
23A - OpenRouter Model - Analysis
32A - OpenRouter Model - Evidence
37A - OpenRouter Model - Executive
```

The current workflow uses:

```text
openrouter/free
```

for the relevance, business-analysis, and evidence stages, and:

```text
liquid/lfm-2.5-2.6b:free
```

for executive synthesis.

Free-model availability can change. If a model is no longer available, select another compatible OpenRouter model without changing the surrounding schema-validation logic.

Do not paste an API key directly into a Code node, prompt, or exported JSON.

## 3. Configure Tavily

The workflow uses Tavily in two places.

### Discovery

Assign a Tavily credential to:

```text
12 - Tavily Search - Brands
```

This stage currently searches the specialist source:

```text
digiato.com
```

### Cross-validation

Create an n8n **HTTP Header Auth** credential and assign it to:

```text
28 - Tavily Cross Validation API
```

Use:

```text
Header name: Authorization
Header value: Bearer <YOUR_TAVILY_API_KEY>
```

The real key must remain inside n8n Credentials and must not be committed to GitHub.

## 4. Verify the RSS feeds

The current RSS collection layer is:

```text
Mehr
https://www.mehrnews.com/rss

KhabarOnline
https://www.khabaronline.ir/rss

Tabnak
https://www.tabnak.ir/fa/rss/allnews

Zoomit
https://www.zoomit.ir/feed/
```

Run these nodes individually before the first full workflow run:

```text
03 - RSS - Mehr
05 - RSS - KhabarOnline
06 - RSS - Tabnak
07 - RSS - Zoomit
```

Each node should return feed items without an HTTP error.

RSS endpoints are external dependencies. A publisher can change, remove, or restrict a feed at any time.

## 5. Review the OSINT configuration

Open:

```text
02 - OSINT Config
```

Current defaults:

```text
Company: Digikala
Competitors: Snapp Shop, Torob, Technolife
Lookback: 14 days
Country: IR
Language: fa
Max items per source: 20
```

The company and competitor keyword arrays are used by the RSS normalization and Tavily search stages.

## 6. Run a manual test

Start with:

```text
01 - Manual Start
```

Follow the execution in this order:

```text
Collection
→ Normalization
→ Merge
→ Deduplication
→ Source ID assignment
→ Semantic relevance
→ Business analysis
→ Rule-based impact
→ Confidence and verification routing
→ Independent evidence check
→ Executive synthesis
→ Citation validation
→ Dashboard generation
```

The validators are intentionally strict. A validation failure usually means an AI output does not match the required schema or is not supported by the available evidence.

## 7. View the dashboard

The HTML report is generated by:

```text
40 - Generate Management Dashboard
```

It can also be returned through:

```text
41 - Dashboard Webhook
42 - Serve Dashboard
```

Current webhook path:

```text
digikala-osint-report
```

The report includes clickable original-source links.

## 8. Credential placeholders in the public JSON

The sanitized workflow uses placeholders such as:

```text
REPLACE_WITH_OPENROUTER_CREDENTIAL
REPLACE_WITH_TAVILY_CREDENTIAL
REPLACE_WITH_TAVILY_BEARER_CREDENTIAL
```

After import, select your own credentials in the corresponding nodes.

## 10. Activation

Keep the workflow inactive while testing.

Only activate it after:

- Credentials are assigned
- RSS nodes work
- Tavily requests work
- OpenRouter models return valid JSON
- The dashboard renders correctly
- Webhook exposure is acceptable for your environment
